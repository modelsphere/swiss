swissd is installed as {{ include "swiss.fullname" . }} in {{ .Release.Namespace }},
serving cluster "{{ .Values.config.cluster.name }}".

Reach it:
{{- if .Values.ingress.enabled }}
  https://{{ .Values.ingress.host }}
{{- else }}
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "swiss.fullname" . }} 8080:{{ .Values.service.port }}
  open http://localhost:8080
{{- end }}

{{ if .Values.auth.disabled -}}
NO LOGIN. server.auth.disabled is set, so everything swissd serves is open to
anyone who can reach the Service. Turn auth.disabled off before this is
reachable by anybody but you.
{{- else -}}
Log in as "{{ .Values.auth.username }}". The password was
{{- if .Values.auth.existingSecret }} set in {{ .Values.auth.existingSecret }}, which you manage.
{{- else if .Values.auth.password }} set in your values file.
{{- else }} generated on first install; read it with:

  kubectl -n {{ .Release.Namespace }} get secret {{ include "swiss.authSecretName" . }}     -o jsonpath='{.data.password}' | base64 -d; echo
{{- end }}

To change it, edit that Secret. The kubelet updates the mounted file within a
minute or so and the next login uses it -- no restart. Every session issued
against the old password stops working, which is the only way to end one early.

FIRST RUN: there is no site profile yet -- this chart no longer writes one.
Log in and the setup page asks for it, pre-filled with a working default.
{{- end }}

Check what it can actually see -- /readyz reports the cluster, the profile and
the catalog separately, so a failure names the dependency:

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "swiss.fullname" . }} -- true 2>/dev/null \
    || echo "(no shell in the image -- use the port-forward above and curl /readyz)"

RBAC is {{ .Values.rbac.scope }}.
{{- if eq .Values.rbac.scope "namespaced" }}
swissd can see releases in: {{ join ", " .Values.rbac.namespaces }}
A release in any other namespace is invisible to it -- not reported as
untracked. Add namespaces to rbac.namespaces as they appear.
{{- else }}
This grants read access to every Secret in the cluster, because helm stores
releases in Secrets and RBAC cannot filter a secret read. It buys a complete
untracked-release view. Make sure that trade was deliberate.
{{- end }}

Swiss does not deploy Swiss: upgrade this release with helm or helmfile, never
through its own UI.

UPGRADING FROM 0.3.x, WHERE THE CHART CREATED THE SITE PROFILE: helm deletes
what it no longer renders. Hand the ConfigMap to swissd before upgrading, or
lose what is in it --

  kubectl -n {{ .Release.Namespace }} annotate configmap {{ include "swiss.fullname" . }}-profile     helm.sh/resource-policy=keep
